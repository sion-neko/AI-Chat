# 0002 会議の録音と文字起こし（保留）

- 日付: 2026-10-28
- 状態: 保留（TODO。音声まわりは手間がかかるので後回し。2026-10-28）

## やりたいこと

Google Meet の会議を録音して文字起こしし、ファイルに保存して、あとから「あの会議で決まったこと、その後どうなった？」のように聞けるようにする。
会議の中身は秘密を含むので、音声も文字も外部のAIに出さない。

## 決めたこと

- 音声は、文字起こしがすべて済んだら既定で消す。聞き直したい会議だけ「残す」にできる
- 埋め込み（ベクトル検索）は作らない（SPECの方針どおり）。全文検索と所員の言い換えで探す

## 提案

### 録音：アプリの画面から録る

- アプリに「録音」ボタンを置き、ブラウザの画面共有で Meet のタブの音声（相手）を、同時にマイクで自分の声を、**別々に**録る
- 2つを別々に文字起こしし、「自分／相手」を付けて時刻順に並べる（手元での話者分離は重いので、最初はこれで割り切る）
- 数十秒ごとにサーバーへ送っておき、ブラウザが落ちても録った分は失わない
- 弱い点: 録音中はこのアプリのタブを開いたままにする。イヤホンなしだと相手の声がマイクにも入るので、イヤホンを勧め、ほぼ同じ文が重なったら片方を落とす
- 録音することは、参加者に伝えるなど社内のルールに従う

ほかの案:
- Meet の録画・文字起こし機能を取り込む: 話者名は付くが、Workspace の設定と Drive の OAuth が要り、Google Chat と同じ壁に当たる
- Chrome の拡張機能: 録り始めは楽だが、配布と承認の手間が増える

### 文字起こし：送り先を差し替えられるようにする

- OpenAI 互換の `/v1/audio/transcriptions` に送る。`.env` の `TRANSCRIBE_BASE_URL` / `TRANSCRIBE_MODEL` で送り先を決める
- 既定は同梱のコンテナ（faster-whisper、CPU）。社内に文字起こしの API が立てば、そちらに切り替える
- 送り先がローカルか外部かを、LLM と同じく画面に出す（app/destination.py）
- メモ（全体・フォルダ）に書いた社内の呼び方を、Whisper へのヒント（prompt）として渡し、固有名詞の聞き取りを良くする
- CPU では1時間の会議に数十分〜1時間かかる見込み（要実測）。毎日使うなら社内 API が欲しい

### 処理の流れ

録音・ファイル → 10分ごとに区切る（ffmpeg）→ 区切りごとに文字起こし → 時刻つきでつなぐ → 所長が要約（決まったこと・宿題・未決）→ 全文検索に入れる

- 全体を調査と同じく裏で走らせ（app/jobs.py）、終わったら通知する
- 区切った音声と、済んだ区切りの文字はディスクに置き、アプリが止まっても続きから再開する

### 保存

- `data/meetings/<日付>_<題名>/`: 音声（消すまで）、時刻つきの文字起こし（Markdown）、要約
- DB: `meetings`（題名・日時・長さ・状態・フォルダ・音声を残すか）、`meeting_segments`（開始・終了・自分/相手・文）
- `meeting_segments` を FTS5（trigram）に入れ、日本語でも部分一致で引けるようにする
- 会議は案件のフォルダに入れられる（フォルダのメモが効き、案件ごとに探せる）

### 画面

- サイドバーに「会議」の一覧を置く（調査の一覧とは分ける）
- 会議の画面: 要約、時刻つきの全文（自分／相手）、「この会議について聞く」
- ファイルの取り込み（音声・動画、Meet の文字起こしのテキスト）と、録音のボタン

### あとから聞く

- 「会議」を検索ソースの1つにする。ツールは `search_meetings(query, since, until)` で、該当の発言を前後と時刻つきで返す
- 出典は「会議の画面の◯分◯秒」へのリンクにする（今の出典の照合がそのまま使える）
- 会議とほかのソース（Zulip・GitLab など）をまたいで、所長が経緯をまとめる

## 進める順番

1. ファイルを取り込んで文字起こし → 保存 → 「会議」ソースで検索（先に Whisper の速さと精度を確かめる）
2. アプリから録音（自分／相手つき）
3. 要約と会議の画面、必要なら話者分離

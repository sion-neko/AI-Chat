# 0001 調査を画面から切り離して走らせる

- 日付: 2026-10-27
- 状態: 採用

## 背景

ローカルLLMでの調査は数分かかる。これまでは質問のPOSTのレスポンスで進み具合を流していたため、

- 調査中に別の調査を開くと、進み具合を見失う（保存はされるが、開き直すまで分からない）
- 画面をリロードすると、進み具合が見えなくなる
- 待っている間に別の質問を並行して頼めない
- 終わったことに気づけない（タブを裏に回していると特に）

## 決めたこと

- 質問のPOSTは調査を始めて `{turn_id, conversation_id}` をすぐ返す。調査はサーバーのスレッドで最後まで走る
- 進み具合は `app/jobs.py` に調査ごとに溜め、`GET /api/events` の1本のストリーム（NDJSON）で、つないでいる画面すべてに配る
- つないだときは、調査中のものを始めから流し直す（リロード・つなぎ直しで続きが見える）。流し終えたら `ready` を送り、画面はそこで「つなぎ直す前の調査のうち、もう終わったもの」を知る
- 同じ会話では1件ずつ、別の会話なら並行して調べられる（LLMを同時に呼ぶ数は `LLM_CONCURRENCY` で別に抑えている）
- 回答が届いたら会話に未読の印をDBに付け、画面が読んだら外す

## 考えたほかの案

- **調査ごとにストリームを開く**: ブラウザは同じホストへの同時接続を6本程度に制限するので、並行する調査が増えると詰まる。1本にまとめた
- **SSE（EventSource）**: 自動でつなぎ直してくれるが、既存の質問のレスポンスと同じNDJSONで揃えたほうが読み書きの部品を使い回せる。つなぎ直しは数行で書ける
- **WebSocket**: 標準ライブラリのHTTPサーバーでは扱いにくく、送る向きも一方向で足りる

## 割り切ったこと

- 進み具合はメモリにだけ持つ。アプリが止まると調査中のものは失われる（起動時に中身のない会話を片付け、画面は中断を知らせて質問を入力欄に戻す）
- 未読の印は会話ごとの1つだけ。どのターンが未読かまでは持たない
